# Codebase Structure & Architecture

This document provides a technical map of the **Alfajr E-Learning** repository, explaining the purpose of key directories and the overall architectural patterns.

## 🏗 Directory Overview

### 📂 Root Directory
- `capacitor.config.ts`: Native app configuration (app ID, plugin settings).
- `next.config.ts`: Next.js specific build and routing configuration.
- `tailwind.config.ts`: Visual styles and theme definitions.
- `tsconfig.json`: TypeScript compiler rules.
- `simulation.test.ts`: Playwright-based E2E tests.

### 📂 `app/` (Next.js App Router)
- `(admin)/`: Routes for the administrative interface (dashboard, user mgmt, course editor).
- `(auth)/`: Authentication pages (login).
- `(employee)/`: Learning interface for students/employees (catalog, dashboard, course player).
- `api/`: Server-side API routes handling data fetching, progress, and admin operations.
- `layout.tsx`: Root layout with global context providers.

### 📂 `components/` (React Components)
- `admin/`: Components specific to the admin module (e.g., `CourseManagement`, `UserManagement`).
- `learning/`: Components for the learning module, including the `UniversalPlayer` and video logic.
- `shared/`: Generic UI components used across the entire application (e.g., `Button`, `MarkdownRenderer`, `ScreenProtection`).

### 📂 `lib/` (Core Logic & Utilities)
- `firebase/`: Firebase Admin and Client SDK initialization and auth utilities.
- `security/`: Mobile protection logic and screen security helpers.
- `session.ts`: Server-side session management.
- `utils.ts`: Small, reusable utility functions.

### 📂 `context/`
- `AuthContext.tsx`: React Context for managing global user state and authentication.

### 📂 `android/`
- Native Android project generated by Capacitor. Contains gradle files, resources, and the APK build output.

### 📂 `public/`
- Static assets like logos, manifest file for PWA, and APK distribution.

## 🔄 Core Architectural Patterns

### 1. Module Separation
The project is strictly divided into two primary modules:
- **Admin Module**: Focused on content creation, user management, and reporting.
- **Learning Module**: Focused on consumption, video playback, and progress tracking.

### 2. Video Playback (Universal Player)
The system uses a `UniversalPlayer` wrapper based on `Plyr`. It dynamically handles:
- **YouTube Embeds**: Optimized for performance.
- **Direct Uploads**: Plays video files uploaded and streamed securely via Bunny.net Storage & CDN.
- **Security Layers**: Integrates `ScreenProtection` and dynamic watermarking.

### 3. Data Flow
- **Frontend**: Uses React Hooks (e.g., `useEffect`, `useState`) and `AuthContext` to fetch data from Next.js API routes.
- **API Routes**: Act as a bridge between the client and Firebase, enforcing server-side rules and administrative privileges via `firebase-admin`.

### 4. PWA and Native Integration
- **Capacitor** is used to bridge the web application to native Android features (like blocking screenshots).
- **PWAEnforcer** ensures that web users on mobile browsers are redirected to the installed app environment for enhanced protection.

## 💾 Data Models (`types/index.ts`)
- `User`: Identity and roles.
- `Course`: Hierarchical structure (Course -> Sections -> Lessons).
- `Lesson`: Content details (type: `text`, `youtube`, or `video-upload`).
- `Progress`: Real-time tracking of user completion.
